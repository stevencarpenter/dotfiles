# Fast-Moving Package Channel Escape Hatch Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let a named list of CLI tools track `nixpkgs-unstable` while every other package stays pinned to `nixpkgs-26.05-darwin`.

**Architecture:** Add a second nixpkgs flake input that deliberately does *not* `follows` the stable one. `modules/home/packages.nix` instantiates it and selects an allowlist of package names into `home.packages` by explicit reference — **not** via an overlay, so unstable versions never leak into other packages' dependency graphs. An eval-time assertion rejects any package declared in both channels.

**Tech Stack:** Nix flakes, nix-darwin, home-manager 26.05, nixfmt, statix.

**Design:** [`docs/superpowers/specs/2026-07-26-fast-moving-package-channel-lag-design.md`](../specs/2026-07-26-fast-moving-package-channel-lag-design.md)

## Global Constraints

- **Never use an overlay for this.** An overlay rewrites `pkgs.<name>` globally, so stable packages that merely depend on `ripgrep`/`fzf` rebuild against unstable, costing cache hits on packages nobody asked to change. Explicit selection only.
- **The six names must appear in exactly one channel list.** A name in both yields two derivations shipping the same `bin/` entry.
- **Cache gate is mandatory before switching.** `nix build --dry-run` must report every new derivation under *"will be fetched"*, never *"will be built"*. This is the repo's existing rule (`modules/home/packages.nix:112-119`). A switch that source-compiles `ripgrep` on aarch64-darwin is the failure this prevents.
- **Do not touch** `home/.config/zsh/.zshrc`, the mise shim logic, or anything under `modules/darwin/homebrew.nix`. Migrating `railway`/`crush`/`worktrunk` out of Homebrew is explicitly a follow-up (design §7), not this plan.
- **Nix formatting:** `just nix-fmt` / `just nix-fmt-check`, 2-space indent. Do **not** run bare `nix fmt`: this repo's `formatter` output is plain `nixfmt`, which reads *stdin* when given no path, so a bare invocation fails with `unexpected end of input, expecting expression`. The Justfile and `.github/workflows/nix-flake-check.yml:42` both use `git ls-files -z '*.nix' | xargs -0 nix fmt --`. `nix flake check` also runs `statix`.
- **Commits:** Conventional prefix, one line, NO `Co-Authored-By` / AI-attribution trailer (the commit-msg hook strips it; do not emit it).
- **Sandbox:** All `nix`/`git` commands in this plan write outside the allowed roots. Run them with the sandbox disabled on the first attempt (see the `sandbox-preflight` skill) rather than looping on "Operation not permitted".

## File Structure

| File | Responsibility | Change |
|---|---|---|
| `flake.nix` | Declares the second nixpkgs input and passes it through the existing `inputs` specialArg | Modify: inputs block + outputs destructuring pattern |
| `modules/home/packages.nix` | Owns the allowlist, the unstable instantiation, and the double-declaration assertion | Modify: arg list, `let` block, six removals, `assertions` |
| `README.md` | Records why fast-movers live where they do | Modify: bucket-table note (~line 213) |
| `flake.lock` | Pins the unstable commit | Regenerated by nix, committed |

**No new files.** The allowlist deliberately lives next to the packages it governs rather than in `lib/`, because it is package policy, not machine policy — `lib/machines.nix` is strictly the per-host capability table.

## Task 1: Add the `nixpkgs-unstable` flake input

**Files:**
- Modify: `flake.nix:16-20` (inputs), `flake.nix:22-30` (outputs pattern)
- Modify: `flake.lock` (regenerated)

**Interfaces:**
- Consumes: nothing.
- Produces: `inputs.nixpkgs-unstable` — a flake input reachable from every darwin and home-manager module, because `flake.nix:57-60` already threads the whole `inputs` set into `specialArgs`/`extraSpecialArgs`. **No specialArgs shape change**, so the LOCKED v1.0 contract in `docs/external-overlays.md` is untouched and needs no review round.

- [ ] **Step 1: Add the input**

In `flake.nix`, after the `agenix` block (currently ending line 19), before the closing `};` of `inputs`:

```nix
    # Escape hatch for tools whose upstream release cadence outruns the stable
    # channel's backport window — the allowlist lives in
    # modules/home/packages.nix. Deliberately does NOT set
    # `inputs.nixpkgs.follows`: tracking a different channel is the entire
    # point, and unlike nix-darwin/home-manager/agenix this input has no
    # nixpkgs input of its own — it IS nixpkgs.
    nixpkgs-unstable.url = "github:NixOS/nixpkgs/nixpkgs-unstable";
```

- [ ] **Step 2: Add it to the outputs destructuring pattern**

This is the step most likely to be missed. The pattern at `flake.nix:23-30` has **no `...`**, and Nix attrset patterns are strict — a declared-but-unlisted input fails evaluation. Add `nixpkgs-unstable,` after `agenix,`:

```nix
  outputs =
    inputs@{
      self,
      nixpkgs,
      nix-darwin,
      home-manager,
      nix-homebrew,
      agenix,
      nixpkgs-unstable,
    }:
```

- [ ] **Step 3: Verify evaluation and that the lock gained the input**

```bash
nix flake check --no-build --all-systems
nix flake metadata --json | jq -r '.locks.nodes | keys[]' | grep nixpkgs
```

Expected: check passes; the key list includes both `nixpkgs` and `nixpkgs-unstable`.

If `statix` fails on the unused pattern binding `nixpkgs-unstable`, replace the line added in Step 2 with `...` (keeping `inputs@`), then re-run. The attr is consumed via `inputs.nixpkgs-unstable`, never by the bare name, so either form works.

- [ ] **Step 4: Confirm the two inputs resolve to different revisions**

```bash
nix flake metadata --json | jq -r '.locks.nodes | to_entries[] | select(.key|test("nixpkgs")) | "\(.key) \(.value.locked.rev[0:12])"'
```

Expected: two different revs. Identical revs mean the input accidentally follows the stable pin and the whole change is inert.

- [ ] **Step 5: Format and commit**

```bash
just nix-fmt
git add flake.nix flake.lock
git commit -m "chore: add nixpkgs-unstable input for fast-moving package escape hatch"
```

## Task 2: Lift `packages.nix` lists into named bindings (no behavior change)

**Files:**
- Modify: `modules/home/packages.nix:21-137`

**Interfaces:**
- Consumes: nothing from Task 1 yet.
- Produces: the bindings `stablePackages`, `guiFonts`, `devTools`, `devFonts`, `workTools`, and `allStable` (their ordered concatenation). Task 3 filters `allStable` for the duplicate assertion and appends the fresh packages to it.

This task is a **pure refactor**. Its test is that the *set and order of packages* does not move — a far stronger guarantee than eyeballing the diff.

> **Do not use the whole-system `toplevel.drvPath` as the invariant on its own.** `flake.nix:63` feeds `self.rev or self.dirtyRev` into `system.configurationRevision`, so that path embeds the current HEAD commit. It is stable across file edits (verified: appending to an untracked file left it unchanged), but **any commit landing between the before- and after-measurement moves it**, producing a false failure. The `home.packages` drvPath list below has no such dependency and is the reliable invariant.

- [ ] **Step 1: Record the current package set (both hosts)**

```bash
for h in personal-mac work-mac; do
  nix eval --raw ".#darwinConfigurations.$h.config.home-manager.users.carpenter.home.packages" \
    --apply 'ps: builtins.concatStringsSep "\n" (map (p: p.drvPath) ps)' > "$TMPDIR/pkgs-before-$h.txt"
  printf '%-13s %s packages\n' "$h" "$(wc -l < "$TMPDIR/pkgs-before-$h.txt" | tr -d ' ')"
done
```

Expected: `personal-mac 73 packages`, `work-mac 67 packages`. Checking **both** hosts rather than only `personal-mac` is what catches a mistake inside the capability-gated blocks — `work-mac` differs by the `caps.dev`/`caps.gui` gates.

- [ ] **Step 2: Restructure into a `let` block**

Replace the body of `modules/home/packages.nix` (everything from line 21's `{` through the end) with the structure below. **Move each list verbatim — do not reorder, add, or remove a single entry.** Order is load-bearing: `home.packages` is a list, so reordering changes the derivation hash and breaks Step 3.

```nix

  # fully assembled stable set, not just the base list. `with pkgs;` has to be
  # repeated per binding — the original single `with` covered the whole
  # concatenation expression, which no longer exists.
  stablePackages = with pkgs; [
    # ← the existing base list (bat … age), moved verbatim
  ];

  guiFonts = lib.optionals caps.gui (with pkgs; [
    # ← the existing caps.gui font list, moved verbatim
  ]);

  devTools = lib.optionals caps.dev (with pkgs; [
    # ← the existing caps.dev tools list (helix), moved verbatim,
    #   INCLUDING its Swift-toolchain comment block
  ]);

  devFonts = lib.optionals caps.dev (with pkgs; [
    # ← the existing caps.dev font list, moved verbatim
  ]);

  workTools = lib.optionals (identity == "work") (with pkgs; [
    # ← the existing work list (conftest), moved verbatim
  ]);

  # Concatenation order is identical to the original `++` chain.
  allStable = stablePackages ++ guiFonts ++ devTools ++ devFonts ++ workTools;
in
{
  home.packages = allStable;
}
```

Keep the existing file-header comment block (lines 10-20) above the `let`.

## Task 3: Move the six laggards to unstable, guarded by an assertion

**Files:**
- Modify: `modules/home/packages.nix` (arg list, `let` block, six removals, `assertions`)
- Modify: `README.md` (~line 213 bucket table)

**Interfaces:**
- Consumes: `inputs.nixpkgs-unstable` (Task 1); `allStable` (Task 2).
- Produces: `fastMovingPackages` — the editable allowlist; `pkgsFresh` — the unstable package set; a `home-manager` assertion that throws at eval time on a double declaration.

The assertion is written **before** the removals, so it fails first with all six named. That failure is the test.

- [ ] **Step 1: Add `inputs` to the module arguments**

`modules/home/packages.nix:1-8` becomes:

```nix
{
  config,
  pkgs,
  lib,
  caps,
  identity,
  inputs,
  ...
}:
```

- [ ] **Step 2: Add the allowlist, the unstable set, and the assertion — but do NOT remove anything yet**

At the top of the `let` block from Task 2:

```nix
  # ── Fast-moving packages: a per-package escape from the stable pin ────────
  # nixpkgs is pinned to 26.05 (flake.nix:8). That line backports fixes but
  # not new upstream releases, so a tool shipping every few days drifts
  # arbitrarily far behind while a tool shipping a few times a year stays
  # current. Everything NOT named here stays on the stable pin — including
  # transitive build inputs, which is why this is explicit selection and not
  # an overlay.
  #
  # Measured 2026-07-26, stable 26.05 → upstream latest:
  #   mise     2026.5.12 → 2026.7.13  (~2 months, ~15 releases)
  #   uv       0.11.21   → 0.11.32    (11 patch releases)
  #   fzf      0.72.0    → 0.74.1
  #   lazygit  0.61.1    → 0.63.1
  #   zoxide   0.9.9     → 0.10.0
  #   ripgrep  15.1.0    → 15.2.0
  # For contrast, gh / yazi / neovim / delta / bat / fd / btop were all exactly
  # current on stable and are deliberately NOT listed. The lag is a cadence
  # mismatch in specific tools, not a general property of the channel.
  #
  # To add a tool: append its nixpkgs attr name here AND delete it from the
  # stable list. The assertion below fails the build if you forget the second
  # half.
  fastMovingPackages = [
    "mise"
    "uv"
    "fzf"
    "lazygit"
    "zoxide"
    "ripgrep"
  ];

  # A second nixpkgs that deliberately does not follow the stable input. No
  # `config` argument: this repo sets no `nixpkgs.config` anywhere (no
  # allowUnfree, no overlays), so the defaults already match the stable set.
  pkgsFresh = import inputs.nixpkgs-unstable { inherit (pkgs) system; };

  freshPackages = map (name: pkgsFresh.${name}) fastMovingPackages;

  # Names claimed by BOTH channels. `pname or ""` because a few font
  # derivations do not set pname.
  duplicated = builtins.filter (
    name: builtins.any (p: (p.pname or "") == name) allStable
  ) fastMovingPackages;
```

And replace the output attrset:

```nix
in
{
  assertions = [
    {
      assertion = duplicated == [ ];
      message =
        "modules/home/packages.nix: "
        + lib.concatStringsSep ", " duplicated
        + " declared in BOTH fastMovingPackages and the stable package list. "
        + "Each package must come from exactly one channel — delete the stable "
        + "entry. (Two derivations shipping the same bin/ would otherwise "
        + "collide at activation with a confusing file-conflict error.)";
    }
  ];

  home.packages = allStable ++ freshPackages;
}
```

- [ ] **Step 3: Run eval to watch the assertion fail**

```bash
nix flake check --no-build --all-systems
```

Expected: **FAILS**, with `Failed assertions:` naming all six of `mise, uv, fzf, lazygit, zoxide, ripgrep`. This proves the guard actually fires — home-manager collects `config.assertions` and throws (verified in `modules/default.nix:14,51` of home-manager `release-26.05`).

If it passes here, the assertion is wired wrong (most likely `allStable` is not in scope, or `pname` is being read off the wrong value) — fix it before continuing, or the guard is decorative.
